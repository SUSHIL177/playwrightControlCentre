# Playwright Automation Control Center v1.8.0

## What's New in v1.8.0 (import-first advisor with one-click apply, run-time host health, dashboard tag fix)

1. **Test Advisor rebuilt around the imported project (`ImprovementAdvisorService.ts`, `shared/specAnalysis.ts`)**: the analysis is derived COMPLETELY from the specs on disk — a local folder or a repository cloned from any version-control host. No discovery run, no browsers, no execution history: the advisor walks the project root (`*.spec.*` / `*.test.*` / `*.e2e.*`, skipping `node_modules`, dot-dirs, reports, caches; 400-file / 512 KB caps), enumerates every `test()` block via the new `extractTestBlocks()` and reviews each one. All execution-telemetry mechanics are removed (no `last_duration_ms`, `flaky`, `retry_count`, latest-batch label — `TestImprovementAdvice` is now source-only). Works identically on an untouched clone.
2. **Every recommendation shows the exact script change (`TestAdvisorPage.tsx`, `shared/types.ts`)**: all static rules ship a `fix` payload — single `before`→`after` pairs, multi-part `replacements` (e.g. each `waitForTimeout(…)` independently), or additive `insertAtEndOfTest`. The UI renders them as a red/green diff with an *Exact changes to apply* header; the exported Markdown report includes them too. The only non-mechanical call (`long-test` monolith restructure) carries a `test.step()` skeleton with Apply deliberately disabled — structure changes are never auto-written.
3. **Apply button — write the fix directly into the spec (`ImprovementAdvisorService.applyFix/revertFix`, `advisor_fix_backups` table, `intel:apply-fix` / `intel:revert-fix`)**: each finding offers **Apply fix → Confirm & write** (two-step inline confirm showing the target file). Matching is block-scoped (the block is re-extracted from the current file), all-or-nothing per fix, and in-root only; the original file is stored in `advisor_fix_backups` before writing. A *Wrote to spec this session* banner offers **Undo** — revert restores the file byte-identically (it refuses if you edited the file since applying). Applying an issue makes it disappear on the automatic re-analysis.
4. **Host CPU/memory health, during the run and after (`RunHealthService.ts`, `execution_batch_metrics` table, `intel:get-health` / `intel:get-batch-health`)**: while a batch executes, the engine samples host CPU (idle/total delta, all cores) and RAM every 2s. Live readout (`CPU 42% · RAM 8.0/16 GB · load 2.4`) in the docked Live Terminal header and the Execution Center. On completion the aggregate (CPU avg/peak, RAM avg/peak, load peak, samples) persists per batch; the Execution History batch detail gains a **Run health** panel with CPU avg/peak, RAM avg/peak of total, 1-min load peak, wall-clock duration, throughput (tests/min) and retries burned, plus an honest empty state for batches recorded before capture existed.
5. **Dashboard — tooltip font legibility (`DashboardPage.tsx`)**: hovering Passed/Failed slices (and every other tooltip) under *Latest Batch Breakdown* now renders near-white text (`itemStyle`/`labelStyle`) on the dark tooltip surface — no more black-on-dark text you cannot read; legends match.
6. **Dashboard — LATEST / ALL TIME tags no longer cover or truncate text (`DashboardPage.tsx`)**: the tag moved off the label row onto the value row (card stays `h-28`); the label gets the full card width with `min-w-0` + `truncate` + tooltip, the tag is `shrink-0`, and captions stay single-line with full text on hover.

## Hosted web mode — quick start

```bash
npm ci && npm run build
PACC_PORT=8080 PACC_DATA_DIR=/srv/pacc-data npm run start:web
```

The server host needs Node 20+, `git`, and the Playwright browsers (`npx playwright install` on the host) — test execution happens on the server, headless.

Environment variables: `PACC_PORT` (default 8080), `PACC_HOST` (default 0.0.0.0), `PACC_DATA_DIR` (default `~/.pacc`), `PACC_MAX_CONCURRENT_RUNS` (default 2 hosted), `PACC_SECRET` (AES-GCM key for saved Git tokens; auto-generated otherwise), `PACC_SECURE_COOKIES=1`.
