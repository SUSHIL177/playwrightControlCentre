# Playwright Automation Control Center v1.3.2

## What's New in v1.3.2 (reports split, run identity, test artifacts, self-healing)

1. **Reports Center vs Execution History — split (`ReportsCenterPage.tsx`, `ExecutionHistoryPage.tsx`)**: the two screens no longer show the same table. **Reports Center** is a latest-first archive of the *native Playwright HTML reports* — open in browser, share over LAN, reveal in folder, delete (with cascade), result tally bar, status filter, and "Run Full Regression" empty state. **Execution History** is the analytical grid — expandable per-test results drill-in (`history:get-results`), batch comparison via `history:compare-batches` (newly-failing / fixed / consistently-failing with a baseline↔candidate picker), CSV export of any batch, re-run failed only, and cascade delete.
2. **Meaningful execution identity (`ExecutionEngineService.ts`, `batchFormat.ts`)**: new batches mint `RUN-<seq>-<yyyymmdd>-<HHmmss>-<rand4>` with a project-scoped `run_number = COUNT(*)+1`; every surface (Dashboard, Reports, History) displays "Run #7 · Nov 23, 2026 · 07:12:40" via shared `batchFormat.ts` helpers instead of the cryptic id (legacy `EXEC-*` ids still load fine). The Dashboard trend chart x-axis now labels points `#7 07:12`.
3. **Test Artifacts module (`ArtifactCatalogService.ts`, new `artifacts` route)**: new sidebar entry **Test Artifacts** catalogs *every file your suite writes into the project folder* — data exports, downloads, JSON/CSV payloads, traces, screenshots. Recursive scan with depth/file-count caps (5 000 files, depth 8, 250 MB per-file skip), exclusion of `node_modules`/dot-dirs/build outputs, kind classification (text/image/video/archive/pdf/other), search + kind filters + folder grouping, inline preview (text ≤ 512 KB, images ≤ 8 MB as data URLs), and **read-only** open/reveal via `shell.openPath`/`showItemInFolder`. Nothing is executed, moved or modified; preview/open paths are validated to stay inside the project root. Auto-rescans on execution completion and badges files that appeared since the last scan as **NEW**.
4. **AI Self-Healing — working condition (`FailureIntelligenceService.ts`, `FailureAndHealingPage.tsx`)**: `settings.ai.healingEnabled === false` is now enforced for generate/validate/apply (actionable error instead of silent breakage); validation runs the project's local Playwright CLI directly (`node <root>/node_modules/@playwright/test/cli.js test <spec> --grep <title> --retries=0 --workers=1 --reporter=line`, npx fallback, 120 s timeout, 16 MB cap) instead of a flaky npx invocation; stored `validation_log` is ANSI-stripped and capped at 32 KB; strict-mode `.first()` injection now covers all `page.getBy*` page methods (not just click targets); the spec file is restored in a `finally` even if validation crashes (restore failure is logged as CRITICAL and surfaced in the UI). The proposal card now shows a validation badge, the full validation log (collapsible), the deterministic-engine note (no external AI), and a prominent warning when restore failed.
5. **Dashboard refresh — fixed & meaningful (`DashboardPage.tsx`)**: the Refresh button now shows a spinner while refreshing, disables itself, prints "Telemetry refreshed at HH:mm:ss" on completion, and surfaces an inline error banner on failure. The Folder-Wise chart was replaced by an always-on **AI Failure Category Distribution** chart fed by analyzed failures, with an empty state explaining where the data comes from (auto-analysis after each run / the Analyze button in Failure Intelligence).

## Root-Cause Fixes in v1.3.1 (execution completion, live telemetry, reports)

1. **Crash-on-refresh killed every module after a run (`ProjectDiscoveryService.ts`)**: `buildFolderTree()` read `project.rootPath` from a raw SQLite row (snake_case), so `path.join(undefined, …)` threw → the `tests:get-tree` RPC rejected → `Promise.all` in the renderer rejected → **no state ever updated**. This single defect caused *Dashboard shows 0s after batch completion*, *Test Explorer shows 0 tests*, and *Reports table never displays new batches*. Fixed to `project.root_path`.
2. **All-or-nothing data loading (`App.tsx`)**: `loadProjectData` now loads each feed independently with per-request fallbacks — one failing module can no longer blank the Dashboard, Explorer, Reports, Failures, or Sidebar badges. Deleting/re-importing projects also re-selects a valid active project instead of pointing at a ghost.
3. **Playwright JSON path resolution (`ExecutionEngineService.ts`)**: the JSON reporter emits `spec.file` relative to the *testDir* (e.g. `sample.spec.ts` for `testDir: './tests'`), not the project root — so `test_results.file_path` pointed at non-existent files and `discovered_tests.last_status` never updated. The engine now resolves both base directories, and "Last Status" updates match on title **and** file (absolute or relative) so same-titled tests in different specs don't stomp each other.
4. **Spawn failure no longer wedges the UI (`ExecutionEngineService.ts`)**: a failed `spawn` (missing node/npx) previously left the renderer stuck in "EXECUTING" forever. The engine now finalizes the batch as `failed`, emits `exec:completed-event`, and every module recovers automatically.
5. **Auto-population after completion (`App.tsx` + pages)**: on `exec:completed-event` the app now (a) refreshes all feeds, (b) auto-analyzes failures *offline-safely* (deterministic heuristic engine; external AI provider analysis stays manual), and (c) bumps an `executionVersion` counter so **Flaky Intelligence, Cross-Browser Matrix, Performance Intel and Scheduler** re-fetch instead of showing mount-time data. The Reports badge/list updates optimistically at run start and with real totals at completion.
6. **Failure intelligence input sanitization (`ExecutionEngineService.ts`)**: ANSI color codes embedded in Playwright's JSON error messages are stripped at ingestion — classification heuristics now match ("Application Defect / Suspected application defect") and the UI `<pre>` renders clean text.
7. **Cascade integrity (`index.ts`, `LocalBridgeServer.ts`)**: deleting a batch or a project now removes linked `test_results`, `failure_analyses`, `healing_proposals`, `discovered_tests`, and `schedules` — no more orphaned rows inflating analytics.
8. **Report resilience**: `finalizeExecution` preserves the user's batch description/mode/environment/browsers/tag (INSERT … ON CONFLICT no longer stamps placeholder metadata into existing rows and also syncs `json_report_path`); reports opened from Dashboard/Reports surface errors in-page instead of throwing into the void; batch metadata survives disk-hydration recovery.
9. **Responsiveness everywhere**: sidebar collapses to an icon rail under `md`; tables scroll horizontally with sensible min-widths; explorer stacks panels on small screens; header/KPIs/toolbars/terminal wrap; long paths break safely; all async buttons surface errors instead of silent failures.
10. **Error-state coverage**: Test Explorer, Failure Intelligence (analyze/generate/validate/apply/rollback/reject), Reports (open/host/delete), Scheduler (load/save/delete), Intelligence pages, Settings — every async path now catches, logs and shows an inline message rather than dying silently.

## Root-Cause Fixes in v1.2.0
1. **Windows SQLite Disk Persistence (`db.ts`)**: Replaced `fs.renameSync(tmpFile, filePath)`—which intermittently fails on Windows with `EPERM` when antivirus or Electron reads the SQLite file—with direct atomic `fs.writeFileSync` so every execution batch, report, and discovered test persists across app restarts.
2. **Playwright Config Reporter & Report Capture (`ExecutionEngineService.ts`)**: When a project's `playwright.config.ts` hardcodes `reporter: [['html', { outputFolder: 'playwright-report' }], ['json', { outputFile: 'results.json' }]]`, Playwright ignores `PLAYWRIGHT_HTML_REPORT` / `PLAYWRIGHT_JSON_OUTPUT_NAME`. `ExecutionEngineService` now checks both the isolated artifact folder and the project's default `results.json` / `playwright-report` directory, parses stdout list lines as a third fallback, and copies the native HTML report into the permanent archive.
3. **Instant Test Explorer Discovery (`ProjectDiscoveryService.ts` + `TestExplorerPage.tsx`)**: Uses direct `node.exe node_modules/@playwright/test/cli.js test --list --reporter=json` (eliminating `npx.cmd` overhead) and auto-triggers discovery when switching to Test Explorer if 0 tests are cached.
4. **Live Dashboard Charts (`DashboardPage.tsx`)**: Renders 4 real-time charts (Latest Batch Donut, Passed vs Failed Bar Chart, Pass % Trend Line, and Folder-Wise / Failure Category Bar Chart) immediately upon execution completion.
